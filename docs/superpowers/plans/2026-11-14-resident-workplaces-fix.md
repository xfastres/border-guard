# 居民岗位、移动与资源建筑修复计划

**Goal:** 派遣的居民真实走到对应建筑工作，到岗后仍可移动/调回/改派；资源点不阻挡己方，开发后只显示对应生产建筑。

**Architecture:** 修复当前 v0.29 中已有的 `assignWorker` / `stepWorker` / `r.work` 链路，让正常居民更新优先处理工作和主动移动，避免城堡待机驻点覆盖工作位置。资源身份、自然覆盖和生产建筑分别存储，绘制只显示当前阶段对应的对象。

**Tech Stack:** 原生单文件 HTML / Canvas / JavaScript，Node.js `node:test`，Chrome CDP。

**Spec:** 本次用户的居民到岗、移动、资源地形和建筑外观反馈。基线是本地 `main@6f09d54`，不是旧临时工作树 `ec866f0`。

## 修改方案

1. **居民到岗位置。** 修复 `updateResidents` 跳过 `stepWorker` 的问题。派遣后沿合法路径真实赶路，仅进入对应建筑的工作格才算到岗；工作格画在建筑可见作业区域内或入口紧邻处，不能让居民回主城两旁。建筑详情标明居民、在途/工作/受阻状态。派遣成功不等于到岗，途中不计工作时间。
2. **到岗后仍能控制。** 点击居民可选中，详情提供移动、调回、改派入口，桌面和触屏均可操作。主动移动会暂停当前工作并释放岗位/停靠预约，移动结束保持目的地，不被待机逻辑拉回主城。随后可重新派往原建筑或其他建筑，只有实际到岗才继续工作。调用处和执行处均校验身份、阶段与可达性。
3. **资源地块通行。** 未开发和已开发的农田、木、石、普通矿、富矿和铁矿均不因资源标记或旧树石地形阻挡领主、居民和民兵。统一点击寻路、重算、连续碰撞与合法落点。水域和完整城墙的城门规则按当前模型处理；不能用全图取消碰撞掩盖问题。
4. **开发后清理图标。** 保留资源种类和账本身份；清掉原自然 `cover`、树石/麦田资源绘制和装饰状态，只显示已建生产建筑。开发应原子校验费用/次数/占位，失败不清地形、不扣费，不可重复建筑或重复产出。可见性刷新、开关详情或重绘不能把旧图标画回来。
5. **生产建筑专属外观。** 农场是农舍/耕作区；林场是低矮木棚、锯木区和木堆；采石场是采石工棚、石堆和工具；矿场是矿洞入口、支架/矿车。沿用现有 Canvas 风格，用独立绘制分支，不能落入 `structure` 的箭塔兜底，也不能给工人画上不相关箭塔。富矿、铁矿沿用矿场并有矿种标识。人物在正确绘制层看得见。
