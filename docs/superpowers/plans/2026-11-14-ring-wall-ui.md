# 整圈城墙与参考图 UI 实施计划

**Goal:** 在居民修复之后，交付真实可玩的整圈城墙，以及接近用户参考图布局、颜色和层级的离线游戏界面。

**Architecture:** 复用现有 `wallRings`、边界碰撞、阵营通行与 Canvas 绘制入口，补齐建城/扩地/敌军攻击/破墙/维修的完整调用链。UI 使用实际模型状态，不从 DOM 反推业务，不展示虚构资源和加成。

**Tech Stack:** 单文件原生 HTML/CSS/Canvas/JavaScript、Node.js 22+、Chrome CDP；无需外部运行资源。

**Spec:** 本次对话中的整圈共享耐久、归零整圈倒塌、主城低耐久、用户参考截图，以及最新“城墙和 UI 优化也加上”。先完成 `2026-11-14-resident-workplaces-fix.md`，再执行本文。

## 用户已经确定的规则

- 城墙是一整圈，同圈所有位置共用一条耐久；任意墙面被攻击均扣同一血量。
- 城墙归零整圈同时倒塌，整圈失去阻挡，敌人可进入主城区域；主城仍是最终失败目标。
- 主城耐久降低，破墙后在敌人集中攻击下应很快失守。
- 居民到正确建筑工作、仍可控制；资源点不挡己方；开发后原地形图标清掉，留下对应生产建筑，不能画成箭塔。
- UI 按参考图优化，包含顶部状态、左侧图例/小地图、右侧详情、底部建造、中央三选一。

## 本轮实施默认值与边界

以下是 Codex 为可执行首版选择的默认值，需写入交付报告，不能宣称都是用户指定数值。

- 主城先采用本次对话提出的 **50** 耐久初值，集中攻击后 **5–10 秒**失守是测量目标，不是未经实测的承诺。所有 UI、恢复、卡牌和升级遵循同一配置；不能让旧增上限卡悄悄把主城恢复到 160。仓库旧重构草稿的“两击主城”与本次对话不同，本轮采用 50 耐久方案。
- 主城建成即有一圈完整墙，墙初始 **600** 耐久，墙与主城各自显示。扩地重算四连通领地的外边界；不增加当前血量或最大值，不复制墙；若校验失败完整回滚。禁止从逐格建墙入口继续摆出第二套防御系统。
- 墙沿格边绘制并碰撞，采用现有 `edge.a/b` 表示，不能把一格宽领地全部堵成实心。每圈至少一个合法城门，己方只能经门跨越完整墙，敌方不能经门穿墙。水仍阻挡双方。敌军森林/山体规则保留当前阵营规则。
- 点击任意墙边都选中所属圈。白天按损失比例收费一键修满（建议满额 12 材料，最少 1；不扣行动），不顺带回血主城。夜间 **6 材料、持续 6 秒、每圈每夜一次**紧急施工，城墙破掉立即取消，夜间不能重建已破墙；暂停/卡牌/后台切换均冻结，恢复不补跑。白天可按同一满额费用重建倒塌的圈，不恢复已损失其他资产。
- 主城与有明确围墙的营地各用 ringId，分别承伤和倒塌；不让某营地破墙伤害主城圈。无围墙营地不造虚构圈。首版不扩大为两圈合并/嵌套/复杂塔资产迁移系统；原有可用塔保留其既有位置和射击规则，不能因本次绘墙被复制或免费升级。
- 视觉尽量接近参考图的深绿玻璃面板、暖金按钮、明晰图标、绿色耐久条、连续墙角和蓝顶主城。沿用 Canvas 自绘素材，改进主城/地表/树木/水面及建筑层次；不能用整张参考图当背景来冒充可交互地图。
- 顶栏显示本游戏实际的金币、材料、粮食、人口、行动、天数和时钟（标签必须准确）。不把同一个材料余额分别冒充木材和石料，不引入本轮无关的资源经济重写。

## Review Focus

- 画了完整圈却没有真实阻挡/敌军无法拆：真实敌军更新端到端。
- 墙破后下一帧仍有碰撞、另一圈一起倒：原子倒塌与多圈独立测试。
- UI 右侧详情遮住居民选择或手机无法关：实际触屏坐标回放。
- 卡牌/暂停冻结了敌军却未冻结施工：同一模拟时间断言。
- 扩地或重建白送回血/复制塔/清工作岗位：资源账本、实体数量和居民原任务测试。
