# 《边境守卫》世界、战役节奏与战斗反馈 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 用户已指定由 Cursor 执行；不必迁移工具或引擎。

**Goal:** 形成可观察经营、可理解碰撞、有持续敌军压力和清晰命中反馈的五夜战役，完整正常流程首轮目标约15–18分钟。

**Architecture:** 延续原生Canvas单文件离线游戏，按v0.22、v0.23、v0.24顺序复制前版演进。共享地形/碰撞与导航规则、显式波次队列、唯一命中事件；经营业务仍使用已有状态和收支入口。

**Tech Stack:** HTML/CSS、原生JavaScript、Canvas2D、Web Audio；验证复用Node与本机Chrome，不新增运行时依赖。

**Spec:** `docs/Border-Guard-v0.21-体验复审与改进设计.md`，必须与本计划一起阅读。具体数值、占地规则、波次表和容错规则以该设计为准。

## Global Constraints

- v0.17–v0.21历史HTML和对应历史测试证据保留；不直接覆盖产品基线。
- 固定HUD的布局、尺寸、定位和响应式规则继续锁定；双端触摸350ms/滑动阈值/PC操作继续复用。
- 地图平移仅由mapWorld既有translate3d控制；碰撞和业务用世界格单位，特效不能污染相机坐标。
- 资源收入走addIncome，支出走pay/spend；击杀、伤害、到岗、结算均不能重复触发。
- 无新框架、无DSH迁移、无联网资源依赖；最终双击HTML可玩。
- 新版有意改变时长、波次、结转和奖励口径；不要要求新版仍然产生旧版固定26杀与39/2/10库存，也不要删除与这些无关的回归检查。
- 本次交付是三个可玩的版本，依次实现，不把第一阶段改成半成品后直接跳到美术。

## Review Focus

1. 新障碍不能把出生点、A/B城址、基础资源、秘点和居民返程堵死；任务1/2负责自动化多种子检查。
2. 派驻/撤回途中建墙或拆墙，居民应重算或明确等待，不能穿墙/瞬移/提前付费到岗；任务2负责。
3. 最后一箭在飞行、最后一兵死亡、首领演出和重新开局相邻发生，不能重复伤害/结算或遗留旧事件；任务4/5负责。
4. 密集敌军停刷与历史队列并存，真正清场可天亮，未出场首领绝不能胜利；任务3负责。
5. 触屏、DPR2、缩窗、地图露底和弱化效果模式中，HUD/选格/手势维持原有稳定行为；任务5负责。

## Task 2：v0.22 居民、民兵、朝向与遮挡

**Files:** v0.22、residents-v022.js、run-v022-checks.cjs。

**Interfaces:** 消费任务1运动与导航。`getResidentPose(resident,time)`只产生表现状态；`findResidentSlot(resident,anchor)`返回合法工作/待机位。实际居民x/y是有效站位，到岗/回家通过距离与业务状态判定，不能只换贴图就完成业务。

- [ ] 补充状态断言：home/posted/waiting/hurt以及在途状态每ID恰好一个可见单位；dead不再活动；民兵绘制数量等于game.militia。
- [ ] 初始两居民出现在城外合法站位；派驻从合法位置出门；工作位与城门目标替换旧建筑中心目标。无空位时排队，不能凭空消失。
- [ ] 接入朝向、待机、行走、劳动、值守、伤员姿态；脚底Y排序与树冠遮挡。朝向/脚步只改美术，不改移动速度和攻击冷却。
- [ ] 路线版本变化时派驻/撤离/护送重算。先验证被堵后等待、拆墙后继续，再验证工资只在真实到岗原入口支付、同周期不重复支付、居民未离营前失守仍受影响。
- [ ] 伤员按夜次ID集合去重；真实维修事件补全统计，分别检查1人4次受击的伤员数为1、两人受伤为2。
- [ ] 检查城堡、营地、树林前后遮挡截图；保存一次10–20秒派驻/工作/撤回演示或连续截图。
- [ ] 完成v0.22更新说明；检查双端手势、地图坐标与HUD矩形，独立提交。此版达到“走路可信、居民可见”即停止追加美术细节。

## Task 3：v0.23 白天、波次、历史兵与经济

**Files:** 创建v0.23、campaign-v023.js、run-v023-checks.cjs；参考DEMO/phaseLimit/makeFront/stopFront/startNight/spawnEnemy/advanceBattle/damageEnemy/contractGoal/rally/renderCommands/nightPreview。

**Interfaces:**
- `createWavePlan(day,frontKind)`返回显式wave列表（dueAt、count、type、gate）及奖励预算。
- 队列由字符串改为稳定记录：`{id,originDay,kind,rewardGold,rewardXp,carried}`；`spawnEnemy`保留票据，`settleKill`仅结算一次。
- `isFrontComplete(front)`只检查本夜参与的波次/等待出场/存活敌人，历史待援队列独立。
- `requestEarlyNight()/cancelEarlyNight()`使用真实白天时钟；`updateHeroRecovery(dt)`每夜一次回场。

- [ ] 添加失败用例：第一组清空但尚有未来波次时不能天亮；末波按表到来；上限阻塞后待出场数不丢失；首领未出场不许赢。
- [ ] 采用设计表的时间、兵量、同屏上限；夜战是分波调度。营地保留有效出生距离、白天预警、原袭营资格。
- [ ] 修改结转与奖励票据：结转不复制奖励，历史队列每夜最多调入新增兵25%，剩余清楚展示；总普通奖励固定为预算，杀敌计数仍按实际人头。
- [ ] 对每夜强制清空所有实际生成敌人的测试场景，断言金币/经验奖励总额恰好等于本夜所生成票据总和，重复伤害死亡对象不再入账；这只是奖励用例，不得充当正常通关证据。
- [ ] “准备完毕”放入既有命令组，3秒取消；增加无城堡风险确认。首日120秒、后续90秒，先保留7行动。
- [ ] 接入有效攻击站位与软分离；总活敌全局上限60，营地与主城额度相加必须在预算内；出生受阻排队，不得出生在实体或营地核心。
- [ ] 号令范围4格、军令阈值、战绩v2和夜次预告同步。测试显示预告、实际兵量、号令命中范围三者对应。
- [ ] 实现每夜一次12秒/40%生命回场，1秒入场保护；第二次本夜倒下不再回场，无城堡倒下失败。暂停/弹窗不倒计时；终局/重开取消回调。
- [ ] 三类正常预算策略分别跑至少seed7/42/99：守家塔防、主动领主、单营地扩张。记录每夜时长、接敌时间、击杀/出场/待援、城损、资源和行动；不得注入资源/生命或人工秒杀来证明可通关。
- [ ] 校准目标：普通玩家愿意操作的完整五夜约15–18分钟；每夜首个普通兵接敌尽量在8–15秒。超过15秒时按设计4.1使用有3秒预告、距目标10–16格且距人物至少4格的合法集结位，不改变入口方向，不在控制区内近脸刷怪；无合法位则用原边缘。不能只加血拖时长。
- [ ] 保留“至少一种普通预算策略可五夜通关”与“故意不布防会受到可辨认损失”两类证据。目标不是让全部策略全程160耐久；发现固定一塔无伤全过就重新调整压力。
- [ ] 分夜income-expense=end-start闭合。写入`v023-*`结果和更新说明，提交；此版关闭时不要求战斗特效完成。

## Task 4：v0.24 唯一命中事件与战斗反馈

**Files:** 创建v0.24、combat-feedback-v024.js、run-v024-checks.cjs；参考attack/fireTowers/damageEnemy/moveEnemy/advanceBattle/finish/fighter/draw/frame。

**Interfaces:**
- `emitCombatEvent({id,kind,sourceId,targetId,amount,x,y})`产生唯一事件供表现消费；伤害只在对应的实际命中逻辑结算。
- `projectiles`与`visualEffects`分离，前者可能影响战斗完成条件，后者只影响画面。
- `resolveHit(projectile)`保证每弹一次；`beginVictoryPresentation()`冻结业务，`finish`只完成一次结算。

- [ ] 领主挥击在设计规定时刻只触发一次伤害；近战墙后目标不命中；自动/手动/移动端攻击仍共用入口。
- [ ] 塔、民兵、驻营守卫先发弹，再在飞行时间后伤害；目标提前死亡、源建筑被毁、弹体到达和同帧终局分别有明确处理（已发射弹可继续，死目标消散）。
- [ ] 最后一发弹体在飞行时不天亮；死亡残影不阻止天亮。暂停冻结战斗弹体和特效；重开清空旧弹体/挥击/死亡/演出。
- [ ] 加入设计第5节闪色、挥砍、方向火花、合并飘字、死亡、城防受击与首领演出。普通敌人视觉受击偏移不能改变x/y与碰撞半径。
- [ ] 首领真正死亡且本夜已清场后先播0.8秒胜利表现，再显示结算；只结算一次，没有普通天亮生产和额外维护。
- [ ] Web Audio首次交互解锁；静音/限流/不支持音频时继续运行。标准/弱化效果只影响表现，两个模式的同种子业务结果相同。
- [ ] 使用已有相机绘制空间做震动、恢复ctx状态；严格验证worldToScreen/screenToGrid坐标往返仍正常，HUD矩形不变。
