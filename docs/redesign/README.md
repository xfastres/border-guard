# Hex World 重构线

> 状态：原型迭代中，不代表正式设计冻结。
> 基线：`fe3e243333ff2123b5c077ae1b9fb3eea6ed8834`（2026-11-17 的 v0.32）
> 当前分支：`redesign/hex-world-foundation`

## 为什么新开一条线

旧版《边境守卫》保留在 `main`，不在这条重构线上覆盖。当前 v0.32 另有存档分支：

- `archive/v0.32-2026-11-18`：保存旧版完整状态。
- `main`：继续保留原项目主线。
- `redesign/hex-world-foundation`：从同一 v0.32 提交建立的全新玩法原型线。

旧版 HTML、文档、测试与会话归档都保留。新原型先独立存在，不把旧系统直接搬进来，也不急着做兼容。

## 新的协作方式

不再采用「先讨论完所有系统，再一次性交给开发」的流程。改为短周期、可试玩的增量：

1. 每轮只解决一个明确的体验问题。
2. 先说清这轮要验证的玩家体验和不做什么；不提前写完整大规格。
3. 做出一个独立可运行的版本，尽量让用户亲自操作，而不是只看说明。
4. 用户试玩后反馈哪里不自然、无聊、看不懂；先定位原因，再决定下一小步。
5. 每轮记录实际改动、验证结果、已知问题和下一轮候选。
6. 没有用户明确确认，不把候选方案称为已冻结规则，不把原型自动并回 `main`。

每个增量都要能回答：
- 这次玩家能做什么以前做不到的事？
- 玩家是否能不靠开发者讲解就理解基本操作？
- 这次实际验证了什么？哪些仍然只是推测？
- 下一步是否应继续、回退或换方向？

## 第一轮：六边形世界地图骨架

本轮只搭出能亲自走进去体验的地图基础，不恢复旧版全部经营和战斗系统。

### 本轮要验证

- 六边形地图是否比旧方格地图更适合这款游戏的世界感。
- 未探索、已探索、当前可见三种战争迷雾是否自然。
- 城堡只提供有限初始视野；领主移动能逐步发现地图。
- 领主在白天和夜晚使用同一套实时移动能力。
- 昼夜切换时领主留在原地，不瞬间传送回城，也不因为探索资源耗尽而无法移动。
- 新玩家能否从简短提示中明白如何移动、探索和查看发现。

### 本轮暂不做

- 完整战斗、敌人波次与首领。
- 资源采集、营地、居民、建筑生产和经济平衡。
- 每日探索力 / 移动点数。
- 科技树、卡牌、遗物、局外成长。
- 把旧版系统整体迁移到新架构。

这些不是被否决，只是暂时不加入，避免一次引入太多变量，无法判断地图探索本身是否有趣。

## 架构原则（先保持简单，随试玩调整）

- 世界地图使用六边形坐标；地图数据与屏幕绘制坐标分离。
- 视野状态与地块真实数据分离：未知信息不能被 UI 提前展示。
- 移动、寻路、视野更新、昼夜时钟、渲染分开组织，避免所有逻辑混在一个事件处理函数里。
- 领主位置是连续游戏状态；昼夜切换不重置位置。
- 地形移动耗时可以不同，但先不叠加每日行动点。
- 每次增量都保持离线可运行，并保留上一个可玩版本。

## 版本状态口径

- **候选**：讨论中的设想。
- **本轮实现**：已进入原型，但仍需要用户试玩。
- **验证通过**：只表示指定验收条件通过，不代表整个玩法已经好玩。
- **暂缓**：当前不纳入实现，不等于永久否决。
- **冻结**：必须由用户明确确认。

不要把自动化测试通过、AI 操作通过或页面能运行，写成「真人试玩好玩」。
