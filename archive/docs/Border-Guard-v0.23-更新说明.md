# 《边境守卫》v0.23 更新说明

日期：2026-11-13。基于 `Border-Guard-v0.22.html` 派生，v0.17–v0.22 历史文件与既有验证证据均未改动。
本版目标：**白天能经营完、夜里有连续分波压力、收益不随兵量膨胀、领主倒下仍有参与途径**。
固定 HUD 布局、相机跟随、双端手势、实体碰撞与居民呈现一行未改。

## 一、这版改了什么

### 1. 白天与夜战时长、显式波次

- 首日白天 `120` 秒、之后 `90` 秒；**行动仍是 7 次、走路不耗行动**。新增「准备完毕 · 立即入夜」放进既有命令组（不是新面板），`3` 秒倒计时内再点一次可取消；会列出真实的未派驻 / 待缴 / 未开发提醒但不强制阻止；首日未建城先弹风险确认。原自动入夜保留。
- 夜战不再是 `1.1` 秒无限刷。每夜一张**显式波次表** `NIGHT_PLAN`，4 组有间隔的攻势，组内按 `0.9` 秒持续出兵，组间留 `>6` 秒喘息；第 1 夜与第 4 夜的兵量、组数、双路结构明显不同。
- 停刷窗口结束**只停刷**，存活敌人必须真实清完才天亮；未出场首领绝不能宣布胜利。
- 远侧入口到城堡可能超过 15 秒：`chooseStagingPoint()` 沿流场在**同一入口方向**找一处距目标 `10–16` 格、距领主与居民 ≥`4` 格、不在领地 / 营地控制区的可站集结位，提前 `3` 秒画「进军」标记后出兵；没有合法位置就继续用原地图边缘。后续波次复用同一集结位，不因玩家站位换点。首领仍从原入口入场。

### 2. 密度、站位与收益预算一起调

- 主城同屏上限 `10/14/18/22/26`，营地上限 `6`，全局活敌上限 `60`；上限阻塞时未出场记录留在 `schedule`，不丢失、不硬塞。
- **有效攻击站位**：目标周围最多 `8` 个真实占位（4 个邻格 × 每格 2 个错位），按「离敌人最近的空位」贪心分配；只有拿到站位的敌人能打建筑，其余在外圈排队，不允许 20 人叠在一点同时伤害城堡。
- 普通兵不再每人固定 `1 金 / 1 经验`。每夜新增普通兵的奖励预算固定为 `6/8/10/12/6` 金与同量经验，首领额外 `8 金 / 1 经验`；用确定性整数均分写到队列记录，生成时带给敌人，击杀时仍走 `addIncome` 与唯一 `settleKill`。营地按 `3+floor(day/2)` 各发对应金 / 经验预算。**没有票据的兵仍计真实击杀并给反馈，但不发资源**。
- 结转放大系数 `1.5 → 1.0`；未出场记录进入明确显示的**待援队列**，每夜最多调入本夜新增普通兵 `25%`（向上取整），保留原票据、不重复发；待援不阻塞天亮，也不宣称继承到新一局。
- 主城成长仍按奖励经验推进（不按新总击杀发十倍卡）。军令「守住阵线」改为本夜计划新普通兵 `50%`（向上取整），「领主亲征」首轮 `5` 名且只计领主真实最后一击。战绩升级 `borderGuard.best.v2` 并写入 `rules:'v0.23'`，不与 v1 击杀纪录直接比较。
- 号令改为**以领主为中心 4 格**，原伤害公式保留；地图画出 4 格虚线范围预览，按钮与战报文案同步，实际目标与预览一致。

### 3. 领主倒下后的参与途径

城堡仍在时每夜最多一次免费回场：`12` 秒后从城门有效空位以 `40%` 生命回场，`1` 秒入场保护；期间不可移动 / 攻击 / 承伤。第二次倒下本夜不再回场，天亮沿用恢复规则。无城堡倒下仍失败。暂停 / 弹窗不倒计时；终局 / 重开立即取消回场。HUD 显示剩余秒数或「本夜回场已用尽」。

### 4. 实测中修掉的阻塞级问题

- **攻击站位方向**：最初按固定顺序给站位，西侧来的敌人被指到城堡东侧，绕路几十秒。改为按距离贪心分配最近合法站位。
- **塔不能被永久当墙**：`seed99` 实测中，玩家把塔建在唯一通路上后，16 名敌人卡在出生点 `1618` 秒、夜战永不结束。现在塔与墙一样是「可被围攻拆除」的实体（敌人不穿过去，但会停下来拆），流场对塔赋 `14` 的高代价；流场的源也包含目标四周的可拆建筑，并在入口不可达时启用兜底源。塔被摧毁会记入当夜建筑损失、使导航版本失效并重算路线。
- **完全重合单位不分离**：`separateUnits` 原来在 `d<1e-5` 时直接跳过，同点出生的敌人永远叠着；改为按 ID 生成确定性微方向拆开。

## 二、最终数值与原因

| 参数 | 最终值 | 原因 |
|---|---|---|
| 首日 / 其余白天 | `120 / 90` 秒 | 首日要读完界面、走图、建城、开发；之后保留经营时间但不再靠倒计时逼人 |
| 行动预算 | `7`（沿用） | 先观察「行动耗尽是否空等」，用主动入夜解决空等，不盲目同时加时间 / 行动 / 资源 |
| 提前入夜倒计时 | `3` 秒 | 够点一次取消，又不至于让「立即」变成再等一段 |
| 停刷窗口 / 末波 | `75/60`、`80/65`、`90/75`、`100/85`、`110/95` 秒 | 末波后至少留 15 秒清场，形成「前中后段」而不是一次倒完 |
| 普通兵 / 主城同屏上限 | `18/10`、`24/14`、`32/18`、`40/22`、`48+首领/26` | 敌军队伍有形状、双路可夹击，但同屏不超过可辨认密度 |
| 波次组数 / 出兵间隔 | 每夜 `4` 组 / `0.9` 秒 | 组间 `>6` 秒喘息；不是单一无限刷，也不靠降速拖时长 |
| 普通奖励预算（金 / 经验） | `6/8/10/12/6` + 首领 `8/1` | 五夜合计约 `42 金 + 8 金`、`43 经验`，只够 2–3 张强化卡；切断「敌人×10 → 金币/卡×10」 |
| 营地奖励预算 | `3+floor(day/2)` 金与同量经验 | 沿用原新增人数公式做预算，营地产出仍主要靠天亮生产 |
| 结转 / 每夜调入 | `1.0` / `25%`（向上取整） | 未出场原量保留；历史兵不挤爆当夜，剩余清楚留在待援队列 |
| 集结位距离 / 预告 / 最小人物距离 | `10–16` 格 / `3` 秒 / `4` 格 | 远侧入口 20 秒以上空跑换成可见集结，不在领地或营地核心近脸刷怪 |
| 有效攻击站位 | `8` 个，错位 `±0.22` 格 | 与脚底半径一致；既形成围城感，又不让几十人同时打城堡 |
| 全局 / 营地活敌上限 | `60 / 6` | 主城 26 + 营地 6 远在预算内，兼作性能上限 |
| 号令范围 | `4` 格 | 需要选时机和站位，不能全图瞬间清兵；预览圈与实际目标一致 |
| 回场 | `12` 秒 / `40%` 生命 / `1` 秒保护 / 每夜 1 次 | 有限容错，不做无限复活；倒下时玩家仍能看懂「多久能回去」 |
| 塔 / 墙流场代价 | `14 / 9.45` | 绕得开就绕，绕不开就拆；避免玩家用建筑把战役卡死 |

## 四、已知限制（如实标注）

- **真人完整试玩：未做。** 全部结论来自源码断言与无头浏览器自动模拟；「约 15–18 分钟」「压力结构不同」是时钟与事件记录，不是玩家主观体验。
- **手机真机测试：未做。** 视口与触摸均为桌面 Chrome 模拟。
- **接敌时间未全部落在 8–15 秒软目标内**：城址 A 的西门距城堡仅 5 格，接敌 3.8–5.6 秒；两个营地夜次因绕行与双线调度到 19.8–20.4 秒。集结位已启用（实测距目标 13 格），但未刻意降低移动速度或加长空跑来凑数。列入真人试玩待观察。
- 主动领主（只留 1 塔）在 seed7 / seed42 第 5 夜失守，seed99 通关：这是策略差异的实测结果，未强行调成「所有策略都能全程无损」。
- 待援队列在本次九组里大多为 0（波次基本能出完），只有营地策略留下 3 名；**「上限长期阻塞 + 大量待援并存」只在单元断言里覆盖，未构成完整通关证据**。
- 战斗命中过程、音效、死亡演出与视觉收尾属于 v0.24；本版关闭时不要求它们完成。
