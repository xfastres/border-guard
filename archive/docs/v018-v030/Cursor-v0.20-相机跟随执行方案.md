# Cursor执行方案：v0.20 仅地图层相机跟随

## 任务

以现有 `Border-Guard-v0.19.html` 为基线，实现领主相机跟随，输出独立 `Border-Guard-v0.20.html`。保留v0.19原件。离线单HTML，不新增依赖、不重构经营或战斗系统。本文件是实现与验收依据；先读取当前代码，不能凭旧版截图重建页面。

用户这次只要求生成方案，由Cursor执行；本方案生成阶段不修改游戏代码。

## 最高优先级：稳定屏幕UI是禁改区

以下屏幕UI保持原DOM结构、层级、定位规则、宽高与响应式规则：标题、暂停/指南/重开、顶部资源HUD、战报、右下探路/目标提示，以及现有建造面板与Bottom Sheet的屏幕布局。

禁止：

- 重写页面flex/grid、重排HUD、改变字号/尺寸/断点、改变UI可见性、重新设计左右角卡片。
- 对body、main、`.layout`、`.field`、`#board`或包含屏幕UI的祖先施加相机transform。
- 为把领主居中而挪动HUD、改变领主真实位置、改寻路目标或移动速度。
- 引入“相机模式”可见按钮、额外移动模式/建造模式切换，或更改已有按钮业务。

允许的改动只有：地图世界层包装与transform、地图视口的平移接管、相机状态/坐标辅助函数、旧平移调用适配、地块面板锚点跟踪、测试。可以只读获取HUD矩形以确定视觉中心，不得写回其布局。

所有地图地形、格子、城堡、资源、领主、居民、敌军、路线与世界标记应一起平移。当前它们已绘制在同一个canvas，无需拆分对象或重写draw中的地形绘制。

## 先核对当前代码，不重复叠加相机

本工作区v0.19实际状态：

- `heroViewport()`、`centerOnHero()`、`followHero()` 使用canvas CSS尺寸与 `board.scrollLeft/scrollTop`；`heroViewport/followHero` 有仅移动端的限制。
- `bindMapGestures()` 的拖图记录 `sx/sy` 并写scroll；`bindVictoryHud()` 的战后拖图也写scroll。
- `tileFromPointer()`、`screenRectOfTile()` 用canvas的 `getBoundingClientRect()` 换算坐标。
- `draw()` 末尾调用跟随；`frame()` 是已有唯一帧循环；`newRun()`、窗口resize、定位领主按钮会触发回中。
- `game.hero.x/y` 是连续格子坐标，已包含角色在格子内的位置，起点例如5.5/4.5；不能再加0.5格。

所以本次不是在原scroll后再加translate。必须统一接管所有地图平移入口。若Cursor中的当前文件已变为transform，则复用已有世界层与相机状态，不再加第二层。

## 选定方案

使用一个独立地图世界层和一个二维相机，PC/移动端共用。地图裁剪视口仍为 `#board`；只对其内部世界层执行 `translate3d(tx, ty, 0)`。

建议结构仅作地图层调整：

```text
#board（原位置、宽高不变；作为裁剪视口）
  #mapWorld（新增或复用；唯一接收相机transform）
    #map（复用原canvas节点，不克隆、不重建）
  原有屏幕HUD子节点（保持原定位，不放入mapWorld）
```

`#board`从滚动平移改为裁剪，清零旧scrollLeft/Top；这是地图视口内部的调整，不能改变其外部几何尺寸。地图不再依赖原生滚动条平移，所有拖拽由现有手势入口转给相机。绘制逻辑继续使用世界坐标，不向每个draw对象额外叠加相机偏移。

### 1. 视觉中心与边界

默认跟随锚点为地图可视安全矩形的中心：

- 先取 `#board` 的可见客户区域与浏览器视口交集。
- 顶部扣除当前实际可见的标题栏、资源HUD占用的横向带状区域。
- 底部扣除当前实际可见的整行命令栏/手机dock占用的带状区域。
- 左下战报、右下目标卡属于局部浮层，不拿它们的矩形将整个地图挤成狭窄区域，不改变任何UI布局。
- Bottom Sheet打开时暂缓相机自动追赶，保持长按选中的地块稳定。关闭后恢复此前模式；不能自动把手动浏览状态重置为跟随。
- 极矮视口没有合理安全矩形时，回退到地图视口中心，不能移动或缩小HUD来凑空间。

只读测量在初始化、resize、横竖屏切换、已有工具栏/抽屉尺寸变化时进行，使用ResizeObserver或已有布局更新入口缓存；不要每帧反复读所有HUD尺寸造成强制布局。

**边缘策略明确采用“居中优先”。** 领主在地图四边四角时仍能居中，允许地图边缘露出原有地图视口背景。不把相机硬限制在 `0..地图宽-视口宽`，否则边缘不可能保持中心。不生成假地块、不改变合法地图范围；点击露出的地图外背景无动作。地图小于视口时也采用同一规则。

本轮不做缩放、镜头震动或惯性。正常跟随直接对齐中心，满足“领主保持居中”；不沿用固定乘0.2导致不同帧率下滞后的旧追赶。手动浏览结束并收到明确回中指令时立即回中，避免新增动画状态。

### 2. 单一坐标口径

相机的 `tx/ty` 使用地图视口局部CSS像素。画布内部世界像素继续使用 `CELL`（或当前同义cellSize），不能把CSS显示宽度当成内部像素。

建议接口（命名可随现有风格调整，但语义必须一致）：

```js
measureCameraViewport() // 返回缓存视口原点、尺寸、安全中心、CSS显示比例
worldToScreen(worldX, worldY) // 世界像素 → clientX/clientY
screenToWorld(clientX, clientY) // client坐标 → 世界像素
screenToGrid(clientX, clientY) // 返回合法tile，地图范围外返回null
setCameraMode(mode) // follow 或 manual
panCameraBy(dx, dy) // CSS像素拖动，只改相机
centerOnHero() // 复用原入口，恢复follow并立即回中
updateCamera() // 使用当前渲染帧的领主位置更新世界层transform
```

令地图视口client原点为 `(vx,vy)`，canvas显示比例为 `(sx,sy)`，相机平移为 `(tx,ty)`：

```text
screenX = vx + tx + worldX * sx
screenY = vy + ty + worldY * sy
worldX  = (clientX - vx - tx) / sx
worldY  = (clientY - vy - ty) / sy

heroWorldX = game.hero.x * CELL
heroWorldY = game.hero.y * CELL
tx = safeCenterLocalX - heroWorldX * sx
ty = safeCenterLocalY - heroWorldY * sy

gridX = floor(worldX / CELL)
gridY = floor(worldY / CELL)
```

比例从当前canvas实际CSS显示尺寸与内部canvas.width/height获得，保持现有显示尺寸与清晰度，不修改地图缩放。devicePixelRatio不能重复乘进CSS坐标。视口原点要考虑board客户区边框；不能同时使用已包含transform的canvas rect，又额外减一次tx/ty。

地图外的grid坐标返回null，禁止像旧tileFromPointer那样把越界坐标clamp成边缘地块。原来的合法性、迷雾、建造资格检查继续由原业务负责。

### 3. 跟随与手动拖图共存

只需两种长期状态：

| 情形 | 相机行为 |
|---|---|
| 正常白天/夜战，鼠标或WASD/触屏移动 | follow；领主渲染锚点保持安全中心 |
| 任意地图手势刚按下、尚未判短按/长按/拖动 | 暂停自动相机更新，避免画面在手指下滑走；不先判定为拖图 |
| 超过现有10px阈值拖图 | manual；清长按计时，关闭面板，按手指位移平移世界层；不触发移动/建造 |
| 拖图松手 | 保持manual，不立即弹回领主；已存在的领主移动不会自行抢回镜头 |
| 新WASD移动输入、新点击/短按移动命令、回城移动命令、定位领主 | 恢复follow；复用原移动业务，不修改路径 |
| 长按350ms打开Sheet | 只检查原目标tile，停止移动等原业务不改；面板期间暂缓自动回中 |
| 短按/长按/取消结束，未形成拖图 | 恢复按下前的相机模式；若短按生成移动命令则为follow |
| 暂停/说明弹窗/切后台 | 不自动推进相机；清理未完成手势，保留位置 |
| 胜利/失败 | 停止跟随；保留最终地图位置，战后拖图与只读查看继续可用 |
| 新一局 | 清理旧相机/手势/锚点，按新领主位置初始化follow |

把原有 `manualPan` 与新模式统一或一对一映射，禁止出现两个彼此覆盖的“手动浏览”开关。取消手势时必须释放“按下暂停相机”的临时锁，不能让后续镜头永久不跟随。

### 4. 现有交互必须保留

PC：沿用当前点击地块/对象打开浮层的入口，按钮与经营/战斗函数不变；WASD与原有点击移动入口照常。此次不新增或改变PC单击语义。

移动端：短按移动、350ms长按高亮并打开Bottom Sheet、按钮≥44px、遮罩/下滑关闭、超过10px拖图、多指取消、pointercancel/失焦清理、兼容click抑制，均保持v0.19规则。不要因引入相机复制第二套手势监听器。

保留全部原有按钮及解锁/扣费/行动逻辑：城墙、箭塔、占领土地、建立营地、居民管理、强化领主、补充民兵、战后休整、回到城堡、高阶领主、高阶塔。

面板锚点：PC已有地块旁浮层若以屏幕坐标定位，保存选中地块grid坐标，调用worldToScreen刷新锚点。只改地图锚点换算，不重写面板布局；沿用其现有视口防溢出策略。移动Sheet保持屏幕固定位置，不跟随世界层。资源tooltip、射程圈、地图路径、战后入口标记遵循同一坐标口径。

## 实施顺序与文件

1. 新建v0.20副本，记录v0.19哈希与各设备HUD几何基线。先定位所有平移与坐标入口；不要先动CSS骨架。
2. 新增失败测试：PC也跟随、边缘严格居中、世界/屏幕往返、地图外不点到边缘、拖图暂停且新移动恢复、HUD不位移。
3. 新增/复用mapWorld，复用原canvas节点和已绑定事件；完成纯相机状态和双向换算。仅此步骤允许修改地图内部CSS。
4. 替换heroViewport/centerOnHero/followHero与现有帧循环连接。相机更新与同一帧领主渲染位置一致，不新开第二个requestAnimationFrame循环，不递归调用sync/draw制造刷新环。
5. 将bindMapGestures、bindVictoryHud、wheel、定位/回城、resize/横竖屏入口改为同一相机API。删除/停用旧scroll平移写入，不能遗留双偏移。
6. 适配tileFromPointer、screenRectOfTile、tooltip与PC地块浮层锚点。普通移动/建造函数、财务账本、敌军与资源生成不改。
7. 跑原玩法与手势回归；旧测试中“拖动后scrollLeft增加”的断言改为“世界层相机位移改变”，不能删除整个测试。保存新测试与截图。
8. 写v0.20交付说明：变更函数、测试、已知限制、截图与文件路径。未经本方案授权的稳定HUD布局变化必须撤回。

## 必须通过的验收

- PC1440×900、1920×1080；触屏横屏844×390、932×430；竖屏390×844。
- 录制/采样直线、对角线WASD与点击寻路；普通follow状态下领主渲染锚点到安全中心误差≤2 CSS px。记录测量坐标，不能只看截图“差不多居中”。
- 四边、四角、地图小于视口时仍居中；暴露的地图外背景不能移动、选中或建设边缘格。
- 至少20个随机合法tile，平移前后world→screen→grid仍返回原tile；边界相邻格不偏一格；canvas内部尺寸、CSS显示尺寸、DPR不同也一致。
- 连续拖图→短按移动、拖图→长按建造、拖图→WASD、打开/关闭Sheet、多指/cancel/失焦都能恢复正确状态。
- 手指按下期间相机不自动滑走；长按不能误移动，拖图不能误扣资源；战后真实触屏点击据点仍能查看只读详情。
- 所有原有按钮仍可达，原费用/行动扣除与解锁条件不变；不靠重建canvas丢失监听器。
- 固定设备与相同UI状态下，让领主移动、相机拖动，屏幕UI矩形的x/y/w/h与基线差≤1 CSS px。比较标题、资源、战报、右下提示，不只是比较根容器。
- resize/横竖屏后只更新相机测量与地图偏移，不改变屏幕UI既有响应式结果；面板和tooltip仍锚定正确地块。
- 原玩法20项、手势10项、原生输入、分夜账目、五夜正常伤害通关继续通过。旧布局断言按稳定UI基线保留。
- 代码检查：相机transform只写mapWorld；无残留的scrollLeft/Top平移写入；无第二帧循环；无屏幕UI布局改动。
