## 4. 第二项：①b′ 硬前提的设计口径

### 4.1 硬前提（E2，`wp3-visual-spec.md` §3.5 L362）

> **390×844 夜战、N=0 灰色「空」在 `drawLighting()` 夜幕暗幕下仍可读。**

判定方式：夜间 N=0 帧实拍（E4 方案，**待 quality-lead 实拍回填 → E5**）。

### 4.2 「可读」的设计判据：可辨即可，不追求发亮

只要求**信息可辨**，不要求亮度或观感与白天一致：

- 灰「空」的**字形轮廓可与 `rgba(84,90,96,.88)` 底区分**，不被暗幕压成不可辨色块；
- 与同帧其它 HUD 文本处于**同一可读层级**（不是「必须比建筑更亮」）；
- 徽章仍随场景受光染色是 ①b′ 的**既有特性**，不得为了「发亮」而破坏 §4.4「夜晚冷蓝」的氛围一致性。

**不判 FAIL 的情形**：颜色比白天略暗、饱和略降；只要可辨即通过。**判 FAIL 的情形**：灰「空」与底色糊成一块、无法读出是「空」→ 触发 §4.3 的回退流程。

> 本判据为**定性可辨**，不臆造对比度数值阈值（规格未给出）。若 quality-lead 实拍后需要数值化，由其与 art-director 另定并回写规格，不由本文件预设。

### 4.3 夹具条件（E2，`wp3-visual-spec.md` §4.1 L477–478）

- 取证人须用 **N=0 的生产建筑**（灰「空」、`assignedResidentIds=[]`），**不要用已派工的到岗帧**：`working` 停 dock 时实色气泡会先遮住徽章左缘，暗幕压暗与气泡遮挡两个效应叠加、无法归因。
- N=0 格无该锚点气泡，可单独量出 `drawLighting()` 对徽章的压暗程度。
- 建议 1440×900 与 390×844 各 1 张，标注「**状态夹具，非自然流程证据**」（E4）。
- **两帧分工**：白天到岗帧 `exp-4-arrived.png` 判气泡遮挡；夜间 N=0 帧判暗幕可读性；两者互不替代（E2 L478）。

### 4.4 不可读时的回退边界：①a + 夜间局部色值微调（**需 team-lead 单独授权**）

若 §4.1 实拍判「不可读」，回退路径为 ①a（`drawLighting()` 之后 + `t.visible` 守卫）+ 按 `phase` 传入徽章色值变量。**四条边界**（E2/E3，`wp3-visual-spec.md` §3.5 L368–378）：

1. **只改颜色参数**；`rrect(36,1,24,15,5)` 的位置 / 尺寸、`label(48,8.5,10)` 的坐标 / 字号**一字符不改**——几何结论（重叠 `x 27.60–34.50 / y 0.77–10.73`、顶边齐平 `y0=0.77`、`exp-4-arrived.png` 左缘判据、EL 的计数与绘制序断言）全基于这两个常量，动位置或字号就要全部重算。
2. **只在 `game.phase==='night'` 生效**，白天走原色值 → 白天到岗帧的 FAIL 判据不受影响。
3. **文案与人数口径不变**：`👤N` / 灰色「空」、`N = productionWorkerCountAt(t)`、与 S4 共用读取口径。
4. **仍是单次绘制**，绘制序下标断言与 `t.visible` 守卫不变；此时不再用「6 行逐字原样包装」的降险捷径。

**授权状态**：该回退**超出** §7 现有「整体移出 + 晚绘画一次」范围，DS 此前「对约束改写无异议」仅是**设计/规格口径确认，不是授权**；**必须由 team-lead 另行书面授权，并把范围写宽到「允许徽章夜间配色分支」**，且按 §0 测试纪律在 WP5 报告附依据。本文件不视为该授权。

## 5. 第三项：同帧复拍验收口径复核（确认 ①b′ 后无需改写）

### 5.1 复述现行判据（E2，`wp3-visual-spec.md` §3.6 L442–445 + `wp2-ux-spec.md` §6 第 4 条 / §8.2）

| 项 | 现行口径 |
|---|---|
| **FAIL 判据** | **`👤` 图标或徽章左缘被实色气泡覆盖** → FAIL；**不是**「徽章不可见」。理由：文字中心 `x=36.80` 在气泡右缘 `34.50` 之外（E3），`N` 数字大概率存活；`label()` 用 `textAlign='center'` / `textBaseline='middle'`，字符串左半 `👤` 会向左伸进气泡区。灰色「空」为汉字、墨迹更宽，同样按左缘判 |
| **触发窗口** | 仅 `r.work.state==='working'` **且居民停在 dock 格**；`N=0`（无气泡）与 `N>0` 在途（气泡锚在居民当前位置）**不重叠**，不用于判此项 |
| **唯一判定帧** | WP2 §6 第 4 条「到岗」那张 `[R]` 截图 `exp-4-arrived.png`；**1440×900 与 390×844 各 1 张** |
| **两帧分工** | 白天到岗帧判**气泡遮挡**（本项）；夜间 N=0 帧判**暗幕可读性**（§4.1 硬前提）。互不替代；报告须分别标注帧用途 |
| **待实拍限定** | 现状遮挡为坐标推算、未实拍；拿到实拍前只记「推算存在遮挡、待实拍确认」，**不写「WP2 已 FAIL」**（E5） |

### 5.2 确认：①b′ 实现后上述判据**无需改写**

理由（E2/E3 推导）：

1. 判据对象是**像素覆盖关系**（`👤` 左缘是否被实色气泡覆盖）与**可辨程度**，与徽章在 `draw()` 内的**绘制时机 / 插入点**无关；①b′ 只改绘制时机，不改判定对象。
2. 判据依赖的几何常量与文案口径全部冻结：`rrect(36,1,24,15,5)`、`label(48,8.5,10)`、`👤N` / 「空」、`N = productionWorkerCountAt(t)`。
3. ①b′ 属 `drawSelection()` 之后、`drawLighting()` 之前，徽章仍受夜幕一致染色；夜间 N=0 帧是**新增取证项**（WP3 执行期），不是对 §3.6 判据的改写，也不改 WP2 验收清单。
4. 代码级断言三案通用（E3，EL 实测口径）：`badgeTextCalls.length === 可见生产建筑数`（不写死 1）、全 `visible=false` 时 `===0`、**`min(badgeIndices) > max(bubbleIndices)`**（所有气泡先于所有徽章）、只按调用序 + 文本过滤不用坐标。与实拍截图互为佐证。
